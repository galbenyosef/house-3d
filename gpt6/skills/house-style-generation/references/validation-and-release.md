# 验收与可选发布

## 根据变更验证

几何、图片、浏览器和上线是不同证据。新风格应全部覆盖；仅入口修复无需重新渲染。已有测试数量、物件数量、发布文件数只是历史结果，不是新的验收目标。

1. `npm test` 检查原有几何与通行；为新风格补必要的实际几何/切换覆盖，不以跳过或放宽断言通过。
2. `node scripts/export-design.mjs` 输出对应手册、CSV 和设计参数，核对名称、材质、尺寸与当前模型一致。
3. 图片验收按 [渲染流程](cycles-rendering.md) 覆盖本次所有新组合，旧图按基线证明保留。保存真实报告，不复制历史 passed。
4. `npm run build` 检查产物，再启动 `npm run dev` 或 `npm run preview`，使用控制台返回的端口与 `/housegpt/` 路径打开 Chrome。

构建成功后若未改代码、不发生新的失败或发现新问题，不为了增加验证次数重复跑相同检查。

## 直接 Chrome 检查

使用当前环境可用的 Chrome 控制工具；不使用内部浏览器或 Playwright，不依赖上一会话的 tab ID、插件路径或调试端口。设备模拟结束后恢复窗口、触摸与网络状态。

| 场景 | 验收内容 |
| --- | --- |
| 新风格直接进入 | `?style=<新ID>`、刷新与本地偏好一致；名称、家具、材质、PBR 与吊灯确为新风格，无未知 ID 法式回退 |
| 实时切换 | 遍历所有注册风格；相机位置、朝向、FOV 保持，碰撞时才复位；改配色/日夜不污染其他风格 |
| 实时操作 | 房间导航、移动碰撞、物件选择与资料下载可用；打开弹窗、失焦、松开方向键后停止移动 |
| 高清入口 | 顶部有清晰“进入高清全景”主按钮；冷启动实时模型未完成时也能进入，不与方向键、房间导航重叠 |
| 高清内容 | 新风格每房与既有风格可切；观察实际图像加载尺寸/当前纹理，不能仅检查按钮文字或 HTTP 200 |
| 高清视角 | 同房切风格保持 yaw/pitch/FOV；换房用对应初始视角；房间与风格标签在加载成功后才切换 |
| 异步与退出 | 快速切换只显示最后目标；加载失败保留原图并可重试；加载中关闭不重新弹出；退出释放全景纹理与事件并恢复焦点 |
| 小屏与横屏 | 320×568、390×844、844×390；至少再看一档平板与桌面；无页面横溢、挡住关闭按钮或点击目标错位 |

每个新生成的房间全景都要环顾完整一周，检查四个方向、拼接处以及顶部/底部极区，确认背后没有穿模、缺面、过近的柜门或异常光斑。透视预览只覆盖正前方，不能代替整张全景的目视审查；记录实际查看范围与发现的问题。

第三种风格不能直接挤进原来为两个按钮分配的手机栏。使用可滚动的风格列表或清晰的选择器，保持当前项可见，主触控目标至少 44 px；“9 个空间 / 风格数量”按实际可用数据呈现。空间不足可省略装饰编号，不能把高清入口藏成含义不明的图标。

验证真实触摸拖动、双指缩放、房间栏滚动与竖横屏转换。屏幕方向依据窗口尺寸，不用全景 canvas 的长宽代替。保留安全区与动态视口高度处理；手机加载 4K、桌面加载 8K，按需保留单张全景 GPU 纹理，避免全屋图片同时解码造成显存压力。

全屏对象应包含工具栏和弹窗，当前应用为 `.app-shell`。原生 fullscreen 若被浏览器环境拒绝，记录回退行为与未验证范围，不把 DOM 父子关系当原生全屏实测通过。

截图与机器读回记录使用本次唯一名称存入 `artifacts/`。Chrome 手机模拟不能写成实体 iPhone/Android GPU 已验证。高清是固定机位的日间默认配色方案图，可环顾和缩放；自由行走与实时配色在 Three.js 模式，不能用“实拍”描述效果图。

## 仅在有发布授权时读取以下步骤

本仓库只提供静态构建及配置示例，部署前先阅读 [部署说明](../../../docs/deployment.md)，确认用户指定的目标域名、主机、版本目录、静态服务和访问前缀。个人服务器拓扑及历史运维记录未收录。新会话没有发布要求时，本地可审查产物即为交付边界；当前会话已授权则继续，不重复确认。

记录现场的活动版本、配置与服务状态。下面的 `current`、`releases` 表示部署端选定的目录结构，不是可以直接写入的预设服务器路径。

沿用已配置的 SSH 身份与主机校验，仅读取凭据来源/元信息，不打印密钥、token 或密码。记录 current 的目标、相关容器启动时间和配置哈希，以便发布后回查。

### 发布顺序

1. 确认本地最终构建、图片和 Chrome 验收通过；生成 dist 全文件列表、长度与 SHA-256。剔除 macOS 元数据，不把 artifacts、源图片、凭据或 Blender 中间导出打包。
2. 使用新的唯一 release 目录，禁止覆盖已有版本。可以全量上传；增量方案只上传变化项，其余项从旧 release 逐项确认哈希后复制到新目录。
3. 在新目录校验**完整文件集合**、长度与 SHA，包括复制复用的文件；资源缺失必须失败，不能由 HTML 兜底假装存在。
4. 切换前再次确认 current 等于预检记录，防止覆盖其他发布。通过临时软链接与同文件系统原子 rename 切到新 release；失败不切，旧目录保留可回退。
5. 原有部署结构不变时无需重启容器、修改共享 nginx、证书或 DNS。若现场与预期不同，重新明确必要变更，不把历史首次部署命令直接重跑。
6. 使用正式域名的严格 HTTPS 校验，核对页面、修改资源、manifest 和新全景；再用 Chrome 检查入口、切房与切风格。回读服务启动时间和配置哈希，区分服务器全量校验与公网抽样范围。

项目现有全量公网对照命令：

```sh
node scripts/verify-deployment.mjs
```

此脚本当前固定正式域名，以三路下载对照本地 dist，写入 `artifacts/deployment-verification.json`。只在要验证该目标时运行；保存旧报告或改为本次唯一输出，避免覆盖历史证据。目标改变时先更新配置。`curl -k` 的 200 不算证书验证通过。

需要回滚时先确认 current 仍为本次版本，再原子切回记录的旧目标；不删除失败目录或更改别人的后续发布。最终提供实际访问链接、release、核验范围与限制，不把本地 build 描述成已上线。
