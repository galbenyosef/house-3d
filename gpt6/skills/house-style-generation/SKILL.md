# HouseGPT 家装风格生成

把用户的风格描述或参考图，落到当前户型的一套真实可切换方案：独立的家具形态、材料与灯光、可复核的尺度、同源模型高清全景。默认保留现有风格与户型关系；参考图片用于提取设计语言，不能代替本户型尺寸依据。

所有命令从包含 `package.json`、`src/layout.js` 的项目根目录运行。此 skill 位于 `skills/house-style-generation/`，根目录是它的 `../..`；在本仓库中应进入 `gpt6/`，不要在仓库根目录执行。无需安装全局 skill，也不依赖 Superpowers。

## 选择本次工作范围

| 用户请求 | 执行范围 |
| --- | --- |
| 新增一种完整风格 | 设计、代码接入、合理性审查、九房预览、桌面 8K / 手机 4K、切换验收、落地资料 |
| 只看预览、先做客厅、只改颜色 | 执行对应房间或材质范围；不把局部结果宣称为全屋完成 |
| 修复入口或手机交互 | 检查受影响 UI；场景来源不变时不重渲图片 |
| 上线、部署到原站 | 完成本地交付后执行发布阶段；同会话已有明确授权可沿用 |

以最新用户要求覆盖历史配色。当前已有 `french`（复古法式）、`italian`（意式轻奢）、`modern`（现代简约）与 `song`（宋韵雅居）；新增风格不重置它们。World Labs 入口已经移除，不在新增风格时恢复。

## 1. 定义风格并核对现场

先读实际代码和 [接入地图](references/style-integration.md)，确认当前已注册风格、房间、材质、导出入口、依赖和现有改动。文档中的分支清单是创建时的地图，代码变化后以当前实现为准。

查看用户提供的参考图，将设计决定写入 `docs/<风格中文名>-设计说明.md`，至少说清：

- 稳定的英文 `styleId`、中文名、来源参考与用户明确偏好；区分“新增风格”与“修改已有风格”。
- 墙、地面、木、石、金属、主软装的色调、实际材料、纹理尺度和光泽；说明哪些部位承担深浅层次。
- 沙发、床、桌椅、柜体、灯具的造型与建议尺寸，以及九房如何沿用同一设计语言。
- 日间与夜间灯光思路、默认配色，以及受原户型和安装条件限制的地方。

用户给的信息足以形成方向时，简短说明假设后继续。只有缺失信息会决定户型、使用人数、范围或付费操作时才询问；不要把已确定的风格重新做成确认问卷。没有新图纸时使用现有 `src/layout.js`，不要重复寻找旧附件。

## 2. 接入实时方案

按 [接入地图](references/style-integration.md) 完成注册、家具、建筑饰面、PBR、灯光、界面、键盘切换和导出，检查所有风格分支。仅向 `STYLE_IDS` 添加名字可能使未接入的模块回退到法式，不能作为完成标准。

复用基础几何和现有资产；风格差异明显的家具、装饰和吊灯使用独立、可重建的几何或 Blender 脚本。记录纹理/模型的来源与许可，用米制尺寸、倒角、正确 UV 和粗糙度获得质感。需要外部资料时查一手来源；参考照不是复制其户型的许可。

保留可用的实时交互：同一视角切风格、房间导航、行走碰撞、日夜与配色、家具选择、清单和截图。新家具占据旧相机位置时才安全复位，并明确反馈。

## 3. 审查设计，再冻结渲染来源

读取 [建筑假设](../../docs/architecture-assumptions.md)、[设计合理性审查](../../docs/设计合理性审查.md) 和 [机位审查](../../docs/panorama-room-review.md)。核对门扇开启、移门停放、家具通道、柜门/抽屉使用、厨房操作、淋浴入口、吊灯净高、收纳与湿区维护。

新增家具以实际世界包围盒、门叶扫掠和碰撞检查为准；不能通过缩小床、移动墙或取消隐私玻璃来美化图片。相机也要检查眼点、视线与近处家具。方案净高 2.8 m、墙厚 0.18 m 为假设，模型与原图的局部偏差仍需在落地资料中保留。

通过相关几何测试和小图审查后，冻结本次几何、材质、贴图、相机与灯光来源，保存源文件哈希及既有全景图片基线。渲染期间不同时改这些来源；有修改就重新导出并记录新的来源版本。

## 4. 生成同源全屋高清

读取 [Cycles 渲染流程](references/cycles-rendering.md)。先确认新 ID 被导出器和 Blender CLI 接受，再用同源场景逐房预览；曝光从本次预览确定，不照抄旧风格数值。

完整新风格选择 `--rooms all`。`remaining` 只表示客厅之外八房，既不是全屋，也不是自动续跑。审查厨房、两卫等小空间后，用原生 8192 × 4096 路径追踪生成桌面全景，再从成品降采样得到手机 4096 × 2048。

只将实际完成且可解码的输出加入清单。保留每房相机、源哈希、渲染参数、成品哈希和手机图来源；不把预览放大为 8K，不以生成式效果图冒充同源空间渲染。

## 5. 验收并交付

读取 [验收与发布](references/validation-and-release.md)，完成与本次范围匹配的构建、几何、图片和 Chrome 检查。第三种及更多风格必须同时在实时与高清模式可选，手机当前风格可见且“进入高清全景”入口明显。

同步导出家具 CSV、落地手册和设计参数，记录已检查项、修正项及现场深化项。用户要求上线或会话已有授权时才执行发布；本 skill 本身不授予远端写入权限。仅在用户主动要求时提交 Git。

最终说明：新增/调整了哪套风格，如何进入和切换，实际生成了哪些房间与分辨率，测试与浏览器检查结果，以及是否已部署。链接到真实产物或访问地址；未运行、局部完成和设备模拟应如实标明，不能把构建成功当作完整验收。
